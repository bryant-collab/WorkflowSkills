# Unslop

Use for a requested writing or editing task and as a prose pass when another skill links here. Do not turn unrelated engineering work into a writing audit. Edit only the requested text; do not modify this skill or publish anything as a side effect.

Read for meaning first, then revise patterns that impede the reader:

- Replace vague claims and unnamed attributions with supported specifics, or remove them. Do not invent sources or measured improvements.
- Cut filler such as “in order to,” gratuitous praise, chatbot closers, and decorative framing. Prefer “use” to “utilize” and the real mechanism to an abstract metaphor.
- State the point directly instead of forcing “not just X, but Y,” artificial groups of three, false ranges, or a generic conclusion.
- Use one name for each concept. Avoid synonym cycling, invented jargon, and concrete-sounding words that do not explain anything.
- Split dense sentences, restore omitted articles and verbs, and name the actor when it matters. Preserve useful rhythm instead of clipping every sentence.
- Reduce distracting punctuation, boldface, decorative emojis, repeated inline labels, and title-case headings when the requested format allows it. Preserve meaningful notation, code, quotations, accessibility cues, and established style.
- Replace feelings with observable facts where the text makes an engineering claim. Keep the user's expressive voice when expression is the point.

Remove redundant hedging, but preserve qualifiers that encode uncertainty, scope, confidence, or limitations. Keep citations, numbers, technical names, operational constraints, and useful documentation accurate. Do not rewrite clear text solely because a word appears in an offender list. Return the revised text in the requested format, with explanation only when it helps review the change.
