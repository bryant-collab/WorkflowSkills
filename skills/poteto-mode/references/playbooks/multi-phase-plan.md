# Plan multiple phases

Produce the requested plan without starting implementation when planning is the deliverable. Ground the scope, repository contracts, affected consumers, actual base, existing checks, and available capabilities. A small task can have a short plan; do not replace a requested plan with code because it appears easy.

Settle observable uncertainties through authorized low-cost investigation or prototypes. Reserve questions for decisions the available evidence cannot settle. Arrange phases by dependencies, with a visible result, editable scope, meaningful checks, evidence, and an exit criterion for each. Performance checks apply to performance claims; live UI evidence applies to UI claims. Do not demand universal ten-lane/performance gates for every change.

Describe one owner for shared state and delivery, optional isolated workstreams, and any requested PR boundaries. Independent PRs and dependent stacks are separate choices. Include compatibility, interruption/restart, test-data cleanup, approval boundaries, and known unavailable surfaces where relevant. Name the active simple execution guide; do not make deferred autopilot machinery a prerequisite.

Validate the plan's paths, commands, dependencies, and acceptance coverage against actual source. No upstream plan checker was ported here, so do not claim one ran. Return the plan path, phase order, evidence requirements, and unresolved decisions. Execution begins only when authorized.
