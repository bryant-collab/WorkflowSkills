# Opening a PR

Use [GitHub delivery](github-delivery.md) for the requested issue-to-PR change or PR repair. Discover the repository's actual base, templates, rules, and checks. Keep one branch and delivery owner, preserve unrelated work, and use an isolated worktree when needed. Never reset a dirty checkout to make a workflow convenient.

Review the diff for correctness, scope, secrets, meaningful documentation, and validation claims. Apply [technical writing](../../../technical-writing/SKILL.md) when the PR text needs it. Follow repository title/body conventions; drafts remain available for incomplete work. Explain the concrete problem and resulting behavior with concise validation and material limits. Attach the PR through the Codex app artifact tool when exposed.

Creating a PR does not start a watcher, post review replies, or authorize merge. A read-only request stops before this playbook. Return the PR link, demonstrated acceptance criteria, current-head check state, and outstanding work.
