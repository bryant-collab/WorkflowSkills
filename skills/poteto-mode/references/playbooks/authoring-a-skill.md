# Authoring a skill

Use the available Skill Creator for the requested creation or revision. Preserve the requested destination, invocation policy, and established format. Include only guidance that changes decisions, with a discriminating description and supporting resources for conditional detail. Do not force a router on a simple skill.

Validate frontmatter, names, unfinished placeholders, relative links, and declared dependencies with the available skill validator and collection checks. These prove packaging. Structural or tool-dependent workflows also need meaningful forward scenarios; subjective style requires user review, not a fabricated behavioral score. Do not claim installation or discovery without observing it.

Return the skill location, choices, exact validation, behavior evidence, and residual gaps. Use [Opening a PR](opening-a-pr.md) only when publishing the authored files is authorized.
