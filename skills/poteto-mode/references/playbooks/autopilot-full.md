# Autopilot-full: deferred program execution

The upstream mode assigns one owner per independent PR through build, verification, review, and merge. Its automatic queue auditing, child reconciliation, countersigns, and fleet lifecycle have no tested replacement in this collection. Do not treat this file as merge authority or launch that fleet.

If requested, produce a concrete program proposal through [Multi-phase plan](multi-phase-plan.md), distinguishing independent work from dependent changes. State each unit's writer, verifier, evidence, current-head checks, resource cap, and the user's actual landing authorization. Prove one full unit with recovery and isolated mutable state before adopting the queue protocol. Explicit messaging, recurring monitoring, and merge rights remain separate.

Until that pilot exists, an authorized single change uses [Feature](feature.md), [Bug fix](bug-fix.md), [Babysit](babysit.md), and [Shipping](shipping.md) as appropriate. Return the deferred capabilities and a bounded practical next step; do not label complex autopilot behavior validated.
