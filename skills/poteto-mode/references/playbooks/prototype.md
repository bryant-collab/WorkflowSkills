# Prototype

Name the empirical or design decision this throwaway artifact will settle. An approved direction constrains the experiment; a read-only explanatory request does not automatically become a prototype. Use a small isolated script or visual sketch suited to the question, without unrelated production architecture or unrequested dependencies.

Compare meaningful variants where the direction is open, using the same inputs and conditions. Observe the decisive behavior, timing, output, or interaction. A visual claim needs screenshots or an available driver; if native UI driving is absent, label that gap. Do not invent exactness from a visual glance.

Keep disposable state separate from retained evidence and clean only owned processes/files. Return the alternatives, evidence, recommendation, and scratch artifact. State that it is a prototype. Production implementation continues under [Feature](feature.md) only when requested.
