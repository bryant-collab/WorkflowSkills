# Hillclimb

Ground a realistic workload and one metric before iterating. Fix a target and a correctness floor from the user's goal; define a bounded attempt or resource budget proportionate to the task. Validate the measurement with [benchmark checklist](../../../benchmark-checklist/SKILL.md), establish the baseline, and keep the harness stable across candidates.

Read and update an installed `show-me-your-work` trail when useful, or use a simple scoped experiment log. One hypothesis names one mechanism. Measure before/after, run the correctness gate, and keep only a justified win. Revert only owned unsuccessful changes. Parallel trials require authorization and isolated worktrees, data, ports, and evidence; the default can be sequential.

Pivot when evidence refutes an approach. Stop at the target, resource limit, user stop, or a demonstrated blocker; a plateau is not proof of success. Do not relax the target or extend scope to manufacture a result. Deliver accepted changes through [Opening a PR](opening-a-pr.md) when requested. Report metric, baseline/final, attempts, accepted changes, rejected hypotheses, and the unmet predicate if any.
