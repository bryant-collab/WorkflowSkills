# Continue one task to completion

Define a checkable done predicate and scope from the user's requested outcome. Continue bounded in-session work, making one evidenced change and verification step at a time. A request to keep working is not permission to broaden the assignment, message others, or publish/merge beyond the granted scope.

For longer work, use an installed `show-me-your-work` trail when available, or a simple durable checkpoint with evidence and the next action. Retry transient failures proportionately; repeated unchanged failure needs a new hypothesis or an honest blocker. Do not weaken the predicate to claim completion or leave speculative fixes behind.

A future wakeup, recurring check, or monitor requires an explicit scheduling request and the supported Codex automation tool. Inspect existing automation first and retain one watcher with meaningful-change notifications. Do not emulate a missing `/loop` command with a daemon, shell cron, or unsolicited recurrence.

Stop at the predicate, a user stop, a required unresolved decision, or a demonstrated inability to progress. Report verified results, retained work, failed attempts, and any unmet criterion. Use [Pause safely](pause-safely.md) only on an explicit pause.
